## Fixed

### BUG - HIGH — in-form AI translate bypassed the per-field narrowing, then Save persisted the raw model output
`lib/phoenix_kit_catalogue/ai_translate_binding.ex`

`AITranslatable.put_translation/4` writes a narrowed, sanitized
translation: a field whose stored translation is `:fresh` (a hand
correction, stamped by the form's Save) is skipped, and
`strip_ai_note/1` cuts a leaked model aside. The AI worker then
broadcasts the RAW `translated` map (`translate_worker.ex:167`), FormGlue
hands it to `AITranslateBinding.apply_translation/4`, and that function
re-prefixed and `force_put_language`d it into the live changeset with no
state check and no sanitizing. Every language tab is an owned data key
(`Web.Helpers.data_owned_keys/2`), so the next Save wrote the raw bucket
over the row — the hand correction gone, with its fingerprint still
saying fresh so nothing would ever flag it. This undercut 0.28.3's
headline ("a re-translate no longer clobbers a hand-corrected sibling")
on the form path.

**Fix:** `apply_translation/4` reads the row once (it already did, for
the fingerprints) and takes each field from the bucket the worker just
wrote; the sanitized payload is only the fallback for a field the row
has nothing for (a `:new` resource, a type without the mechanism, a
field the worker left untouched). Three tests in
`test/phoenix_kit_catalogue/ai_translate_binding_test.exs`.

### IMPROVEMENT - HIGH — a generated slug had no collision handling against a global uniqueness scope
`catalogue/slugs.ex`, `web/item_form_live.ex`, `web/category_form_live.ex`, `ai_translatable.ex`, `catalogue.ex`

Slug uniqueness is one projection `PRIMARY KEY (lang, value)` per entity
kind across every catalogue, and the sync trigger fires on `slug`
changes only, so a trashed row keeps its projection. The forms'
`Slugs.maybe_generate/3` was fully deterministic; the only handling was
the DB constraint. Two supplier catalogues each holding an "Oak panel",
or a "Vase" re-created after its predecessor was trashed, failed Save
with "is already taken" on a field the user never typed. Only the AI
path probed (`-2`, `-3`), and it probed through `get_item_by_slug/3`.

**Fix:** `Catalogue.item_slug_taken?/3` / `category_slug_taken?/3` probe
the projection directly (trashed rows included, the owner excluded);
`Slugs.unique/3` is the one suffix loop; `maybe_generate/3` takes a
`:taken?` probe, which both forms pass, and the AI adapter uses the
same probe. Tests: `slugs_test.exs` (unit), `slug_projection_test.exs`
(DB), `item_form_seo_test.exs` (a trashed predecessor in another
catalogue → `vase-2`).

### IMPROVEMENT - MEDIUM — `Extensions.absorb/3` was unguarded
`lib/phoenix_kit_catalogue/extensions.ex`

`absorb_one/4` called the extension's `cast_*/2` bare and matched only
`{:ok, _}` / `{:error, _}`; `absorb/3` runs on every `validate`, so one
raising or mis-shaped cast crashed the item/category form on the first
keystroke. The `columns/1` doc claimed a resilience contract "same as
`absorb/3`" that only columns actually had.

**Fix:** a raise/throw/exit or a foreign return shape is logged with
the extension and callback named, and that extension's namespace keeps
its current value for the save; siblings still absorb. Two tests plus
`Test.RaisingCastExtension`.

### IMPROVEMENT - MEDIUM — no validation of an extension's namespace key
`lib/phoenix_kit_catalogue/extensions.ex`

Nothing rejected a `key/0` colliding with a catalogue-owned top-level
`data` key. An extension keyed `"en-US"` would have replaced the
English translation bucket on every save — and since
`data_owned_keys/2` lists extension keys as owned, the owned-key splice
let it through. **Fix:** `all/0` drops (and logs once per process) a
key that is not a non-empty string, is underscore-prefixed, is shaped
like a language code, or is in the reserved list (`meta`,
`files_folder_uuid`, `featured_image_uuid`, `media_order`, `pro100`,
`original_unit`, `seo`, `slug`, `selected_value_slugs`). Test plus
`Test.ReservedKeyExtension`.

### IMPROVEMENT - MEDIUM — extension column cells were rendered twice per row
`lib/phoenix_kit_catalogue/extensions.ex`

`run_guarded/5` forced `Phoenix.HTML.Safe.to_iodata/1` on the
extension's `%Rendered{}` to catch a raise buried in its dynamics, then
returned the struct for the template to evaluate again — the
extension's per-row body ran twice per row per render. **Fix:** for a
cell the probe is the render: the guard hands back `{:safe, iodata}`.
Labels are still returned as strings. Test updated.

### IMPROVEMENT - MEDIUM — the test harness replayed this module's chain against a hard-coded `2`
`test/test_helper.exs`

`migrated_version_runtime/1 < 2` would have left every developer test
DB stamped at V2 without V3 the day it ships — the same silent
"never applied" trap the file's own comment warns about for core.
**Fix:** compares against `Migrations.current_version/0`.

## Fixed in 0.30.1 (the same day, on "fix what can be fixed by us")

- **IMPROVEMENT - HIGH — the translation sweep had no failure memory.**
  `candidates/2` was deterministic (sorted by `{name, lang}`, types in
  a fixed order, `Enum.take(max)`), and a terminal `TranslateWorker`
  failure left the row `:missing`, so two hundred consistently failing
  rows were re-enqueued every tick and everything behind them starved.
  **Fix:** the worker reads the `TranslateWorker` jobs Oban discarded in
  the last 24 h and skips those pairs, widening the page by their count.
  Two tests (`translation_sweep_worker_test.exs`).
- **IMPROVEMENT - MEDIUM — value-mode translations were born `:unknown`.**
  **Fix:** `TranslationStatus.stamp_all_translated/1`, called after
  create in both forms; every secondary language holding a translation
  is stamped against the source the row was created with. Unit tests in
  `translation_status_test.exs`.
- **IMPROVEMENT - MEDIUM — stored `sweep_langs` not intersected with the
  enabled languages.** **Fix:** `Web.Settings.sweep_langs/0` filters the
  stored list by `Multilang.enabled_languages/0`; the worker test now
  enables its language like the LiveView tests do.
- **NITPICK — the browse-sort vocabulary pin's fetch-layer half was
  integration-only.** **Fix:** `Search.apply_search_order/2` is public
  (`@doc false`) and the pure conformance test builds every clause.
- **NITPICK — the relay's abandonment needed a second event.** **Fix:** a
  per-refresh `ack_check` timer; an unacknowledged relay exits when the
  window closes. The pre-existing "acknowledged refresh keeps the relay
  alive" test was racy (it never stopped the setup relay, so two relays
  answered the same event) and is fixed alongside.

## Checked and found correct (highlights)

- Migration V2: every statement idempotent, the sync function deletes
  only its owner's rows, `down/1` drops nothing, the marker is stamped
  last; `Item`/`Category` schemas agree column-for-column with the V1
  DDL plus V2's `slug jsonb`.
- Owned-data keys: `apply_owned_data/2` deletes on explicit `nil`,
  preserves unmentioned keys, `FOR UPDATE` inside the transaction; both
  forms' owned lists cover the translatable buckets, extension keys and
  the attachment/meta keys; `narrow_new_data/2` keeps the attachment
  pointers on create; `_translation_fingerprints` is correctly absent.
- Slug write-once: a rename never regenerates; Duplication copies omit
  `:slug`, so copies cannot collide.
- Order chain: `:position` is a total order ending in `i.uuid`; the
  `list_items/1` catalogue join is LEFT (orphans kept, last); every read
  of the persisted shared sort is clamped before `BrowseState.init/1`.
- Vocabulary sync: `BrowseState.order_fields/0`, `TableConfig`'s
  sortable ids, `apply_search_order/2` and the detail LV whitelist agree.
- Image column: no per-row file query; card view no longer duplicates
  the picture; the managed column suppresses the automatic thumb.
- Oban sweep: unique `period: :infinity` collapses boot/settings/tick
  inserts; `max_per_run` honoured; toggle-off mid-chain is a no-op tick.
- Translations page: no DB work on the dead render; catch-all
  `handle_info/2`; subscribes only to the AI topic; every action survives
  `ai_available: false`.
- Gettext: 1,128 runtime strings in `lib/`, all in the `.pot`; five
